# Visual Briefing

Use this reference when the source is clear but the page still needs a stronger visual result.

## Core rule

The best Studio prompts do not only say what the page should contain. They also say what the page should **feel like visually**.

Default rule:

- one page = one visual thesis

That means one dominant object or one dominant composition idea should organize the page.

## What is a visual thesis

A visual thesis is the shortest statement of the page's visual center.

Examples:

- `One dominant timeline explains the story.`
- `One comparison frame resolves the choice.`
- `One scientific figure anchors the method page.`
- `One chart owns the page, with sparse annotation around it.`

If a page does not have a visual thesis, it usually falls into equal-weight cards, generic support panels, or dense copy clusters.

## Dominant object beats equal peers

Prefer:

- one main chart
- one main figure
- one main matrix
- one main workflow strip
- one main hero area with a smaller evidence rail

Avoid:

- four same-sized cards
- two equal columns with long paragraphs
- several competing mini-charts
- multiple highlighted blocks with no clear hierarchy

## When to use each visual posture

### Hero-led

Use when the page needs one main claim with compact support.

Typical fit:

- product intro
- one-slide positioning
- one big judgment with two proof points

### Chart-led

Use when the relationship or trend is the page.

Typical fit:

- news with one main numeric shift
- macro or market analysis
- data-backed argument with one inflection point

### Figure-led

Use when the method, system, or structure needs explanation.

Typical fit:

- research method page
- architecture or system explanation
- scientific diagram page

### Matrix-first

Use when the insight depends on relative position or tradeoff.

Typical fit:

- 2x2 reasoning
- company/product positioning
- strategic or categorical comparison

## Quiet secondary text

Secondary text should support the visual thesis, not compete with it.

Good patterns:

- two or three short callouts
- one caption
- one small implication rail
- compact method labels

Bad patterns:

- long explanatory sidebars
- several dense support paragraphs
- repeated labels around every object

## Strong hierarchy

Hierarchy usually comes from:

- one dominant object
- scale contrast
- quiet secondary copy
- fewer decorative surfaces
- strong placement of the main claim

Do not try to create hierarchy only with bolder words or more color.

## Useful language for prompts

These phrases usually help:

- `single dominant visual`
- `one visual thesis per page`
- `quiet secondary text`
- `restrained annotation`
- `strong hierarchy`
- `publication-like figure`
- `hero + evidence rail`
- `chart-led page`
- `matrix-first page`

## Weak language to avoid

These phrases are usually too vague:

- `make it more premium`
- `make it beautiful`
- `make it feel top-tier`
- `make it high-end`

Replace them with structure, hierarchy, and anti-patterns.
